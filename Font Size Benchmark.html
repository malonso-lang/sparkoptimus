1  What the standards say

Four major references cover font sizing for web. None set a hard legal floor, but they converge strongly around a practical minimum.

WCAG 2.1 — Level AA
16px

No explicit pixel minimum — but defines "large text" as ≥18pt (24px) or bold ≥14pt (~18.66px), which influences contrast requirements. Industry consensus reads the implicit body minimum as 16px.

AA
WCAG 2.1 — Level AAA
18px

Enhanced readability. Recommends 18px+ for body text, and specifically states 18pt (24px) normal or 14pt bold (~18.66px) as the threshold below which full 4.5:1 contrast is required.

AAA
Section 508 / US Federal
15–16px

Recommends 11–12pt (15–16px) for web. Explicitly notes this is not the signage minimum of 16pt — on websites users can zoom, so typical body text at 15–16px is acceptable.

Section 508
Industry / UX consensus
16px

Browser default is 16px. Major design systems (Material 3, Apple HIG, Shopify Polaris) set body at 16px. Secondary/helper text 14px. Absolute minimum for any rendered text: 12px (uppercase-only labels with wide tracking may stretch to 11px).

Consensus
Dyslexia & low-vision research
18px

Academic research recommends 18pt (24px) for users with dyslexia. Even for neurotypical users, studies show reading accuracy improves from 12px → 16px → 18px. Beyond 18px gains diminish for flowing text.

Research
Our working thresholds
16px

Body text minimum. Secondary/UI text: 14px. Uppercase eyebrow labels: 12px acceptable if bold + tracked. Absolute hard floor: 11px (nav group titles only).

22 CSS classes use text below 13px — including readable body-level copy

Body text (16px ✓) and most heading sizes are solid. The problem is concentrated in UI micro-labels, footer elements, and card metadata — all currently set at 11–13px with low contrast on muted colors. These are real readability risks, not just academic ones.

4  The iOS input zoom trap

A frequently overlooked consequence of sub-16px text.

The problem

iOS Safari automatically zooms the viewport to 16px when a user taps an <input> with font-size < 16px. This causes a jarring zoom animation and often requires a manual pinch-out to restore the view.

Affected elements

  • .site-footer__input — 14.5px ⚠
  • .ins-cta__nl-input — 14.5px ⚠

Fix: set font-size: 16px on both. Visual weight is barely noticeable at this scale.

5  Recommendations

Prioritised fixes — high impact first.

1

Raise the --text-xs token from 12px → 13px

This single token change improves ~18 class instances immediately — eyebrows, micro labels, stat labels. At 13px with 0.14em letter-spacing and bold weight, uppercase labels are comfortable to read.

/* tokens.css */
--text-xs:  13px;   /* was 12px */
--text-sm:  14px;   /* unchanged */
--text-md:  16px;   /* body — unchanged */
2

Fix both newsletter inputs to 16px

Prevents iOS viewport zoom on tap. Both .site-footer__input and .ins-cta__nl-input need font-size: 16px. This is a functional bug, not a preference.

/* site.css — line ~401 + ~539 */
.site-footer__input  { font-size: 16px; }
.ins-cta__nl-input   { font-size: 16px; }
3

Raise .pcard__role from 11px → 13px

Job titles on person cards are readable content, not decorative labels. 11px with muted color is a real accessibility failure. The role text communicates key information about each person.

/* site.css */
.pcard__role {
  font-size: 13px;  /* was 11px */
  letter-spacing: 0.06em;
}
4

Raise body-level card copy to 16px

Three components use 14.5–15px for flowing reading text: .tcard p, .numblock__quote p, and .svc-card p. These should follow the body standard of 16px.

.tcard p          { font-size: 16px; }  /* was 15px */
.numblock__quote p { font-size: 16px; }  /* was 15px */
.svc-card p        { font-size: 16px; }  /* was 14.5px */
5

Raise footer micro-labels to 12–13px

Footer column headers (.site-footer__head) at 11.5px with muted color on dark background very likely fail the 4.5:1 contrast requirement. Raise to 12.5–13px and verify contrast ratio.

.site-footer__head { font-size: 12.5px; }  /* was 11.5px */
.site-footer__bottom { font-size: 13.5px; } /* was 13px */
.site-footer__legal a { font-size: 13px; }  /* keep on mobile */
6

Raise card metadata labels from 11–12px

Case card client names (.so-case__client), meta rows (.so-case__meta), and case tags (.so-case__tag) at 11–12px with very low contrast fail on multiple counts. Raise to 13px.

.so-case__client { font-size: 13px; }  /* was 12px */
.so-case__meta   { font-size: 13px; }  /* was 12px */
.so-case__tag    { font-size: 12px; }  /* was 11px */

6  What it's OK to keep small

Not every sub-14px element is a failure — context matters.

Acceptable small text

  • ✅ Nav group titles — 11px bold uppercase, purely structural, glanceable
  • ✅ Keyboard hint labels in search overlay — purely decorative, power users only
  • ✅ Image overlay tags with white text on dark — contrast compensates for size
  • ✅ Filter bar "Filter by:" label — purely structural, accompanies chip filters

Never acceptable small

  • 🚫 Job titles / names on people cards — readable, informational
  • 🚫 Body copy in cards (testimonials, services) — sustained reading
  • 🚫 Input field text — iOS zoom trap + 4.5:1 contrast risk
  • 🚫 Quote attributions — readable content that communicates source credibility
