The three-layer model

Architecture

Images flow through three distinct layers. Each layer has a clear, non-overlapping responsibility. Don't double-process: if Storyblok CDN transforms an image, Astro should pass the URL through, not re-compress it.

Storyblok CDN
Source of truthTransformServe
All production images live here. The Storyblok asset manager is the single source of truth. Images are served from a.storyblok.com (backed by Amazon CloudFront). URL parameters handle every transform: resize, format convert, quality — no build-time processing needed.

Store once, serve transformed on-demand. No duplication, no pre-generated variants on disk.
↓ transformed URL passed to Astro component
Astro
Build-timeHTML generationsrcset assembly
Astro generates the correct HTML markup. The custom <SbImage> component accepts a raw Storyblok URL and assembles a complete <img> with srcset, sizes, loading, decoding, and fetchpriority — all computed at build time for SSG pages, or at request time for SSR.

For local/public assets (logos, icons, pillar illustrations), use Astro's built-in <Image> component from astro:assets.
↓ optimized HTML served via Vercel edge
Vercel
DeployEdge cacheSSR runtime
Vercel does not touch image files directly. The Storyblok CDN handles image serving. Vercel's job is to cache the HTML pages at the edge and run SSR routes on demand. Set Cache-Control: s-maxage=3600, stale-while-revalidate=86400 on SSR page responses. For static output (output: 'static' in Astro), Vercel automatically CDN-caches the HTML at the edge.

Do not route Storyblok image URLs through Vercel's _vercel/image endpoint — that double-processes and adds latency.

Storyblok image service

URL reference

All transforms are URL-only — no SDK required for serving. The /m/ path segment activates the image service and auto-converts to WebP if the browser supports it. Append filters to chain operations.

src/utils/image.ts — utility functions
/** Build a Storyblok image service URL */
export function sbImg(
  src: string,
  width: number,
  height = 0,
  format: 'webp' | 'avif' | 'jpeg' = 'webp',
  quality = 80
): string {
  if (!src || !src.includes('a.storyblok.com')) return src;
  return `${src}/m/${width}x${height}/filters:format(${format}):quality(${quality})/`;
}

/** Build a srcset string for responsive images */
export function sbSrcset(
  src: string,
  widths: number[],
  format: 'webp' | 'avif' | 'jpeg' = 'webp',
  quality = 80
): string {
  return widths
    .map(w => `${sbImg(src, w, 0, format, quality)} ${w}w`)
    .join(', ');
}

/** Usage examples */
sbImg(url, 1200)
// → https://a.storyblok.com/.../image.jpg/m/1200x0/filters:format(webp):quality(80)/

sbImg(url, 1200, 0, 'avif', 75)
// → .../m/1200x0/filters:format(avif):quality(75)/

sbSrcset(url, [400, 800, 1200])
// → ".../m/400x0/.../ 400w, .../m/800x0/.../ 800w, .../m/1200x0/.../ 1200w"

Astro components

Implementation

Two patterns cover all cases: the built-in <Image> for local/public assets, and a custom <SbImage> for everything that comes from Storyblok. Never mix the two for the same image.

astro.config.mjs — required config
import { defineConfig } from 'astro/config';
import { storyblok } from '@storyblok/astro';
import vercel from '@astrojs/vercel/serverless';

export default defineConfig({
  adapter: vercel(),
  integrations: [
    storyblok({ accessToken: import.meta.env.STORYBLOK_TOKEN }),
  ],
  image: {
    // Allows Astro <Image> to process Storyblok remote images
    domains: ['a.storyblok.com'],
    remotePatterns: [{ protocol: 'https', hostname: 'a.storyblok.com' }],
  },
});

Loading rules

LCPCLSLazy

Three attributes control loading priority. The combination you choose depends entirely on whether the image is above or below the fold. Never apply loading="lazy" to an LCP image — it delays the most important paint on the page.

Above fold — LCP candidate
loading="eager"Start fetching immediately (browser default but explicit is safer)
fetchpriority="high"Elevates request to highest queue — critical for LCP
decoding="sync"Block rendering until decoded — avoids blank flash
<link rel="preload">In <head> — browser finds image before parsing <body>
width + heightRequired — browser reserves space, prevents CLS
priority (SbImage)Shorthand that sets all four attrs above automatically
Below fold — deferred
loading="lazy"Defers fetch until image enters viewport — native browser API
fetchpriority="auto"Omit this attribute — "auto" is the default
decoding="async"Off-thread decode — reduces jank during scroll animations
width + heightStill required — space reserved before image loads
(no preload)Preloading below-fold images defeats the purpose of lazy loading

✓
Quality recommendation: 80 for photography, 90 for illustrations

Quality 80 is the default for all editorial photography (heroes, cases, team portraits). Bump to 90 for illustrations and flat-graphic images where compression artefacts are more visible. Never go below 70 — WebP artefacts at low quality are worse than JPEG at equivalent settings.

7

Run Lighthouse on the homepage, cases page, and team page. Target: LCP under 2.5s, CLS under 0.1. The three fixes in steps 1–3 should get you most of the way there. Check that no lazy-loaded image has fetchpriority="high" and no LCP image has loading="lazy".

Rule of thumb

Every image on the site should ultimately live in Storyblok and be served through the /m/ image service. Local site/assets/ is only for files that are design-system constants — logos, icon SVGs, pillar illustrations — that never change per-page and are not managed by editors.

If an image is ever expected to change (hero photography, team portraits, case images, insight thumbnails), it belongs in Storyblok, not in the codebase. The naming convention ensures the Storyblok asset manager stays navigable as the library grows.
