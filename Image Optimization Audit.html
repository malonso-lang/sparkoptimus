Image Optimization Audit

What to change,
where, and why.

A complete review of image loading practices across the SparkOptimus website rebuild — covering format, sizing, lazy loading, LCP, and CLS across all pages and components.

Critical High priority Medium priority Low / polish

Summary

No image on the site currently uses `loading="lazy"`, `fetchpriority`, `width`/`height` attributes, or `srcset`. This means every image loads eagerly on page load regardless of whether it's visible, causing unnecessary bandwidth use, layout shift (CLS), and slow initial renders.

Three images are critically oversized for their display size: placeholder-case-executive.jpg is 2.4 MB at 4928×3264px but displayed at ~380px wide. The two main hero backgrounds are also 1.3–2.7 MB JPEGs with no preload strategy. The hero video has no poster frame, so users see a blank black screen until the video starts. Fix these five things first — they account for the vast majority of the performance deficit.

Critical LCP impact

These issues directly delay the Largest Contentful Paint — what the browser paints first and what Google measures for Core Web Vitals.

Critical
Hero video has no poster frame
hero.jsx → <video>
Why it matters

Without a poster attribute, the browser shows a blank black area until the video file has downloaded enough to decode the first frame. On slow connections this can be several seconds — and it's the very first thing users see. This is likely the single biggest perceived-performance problem on the homepage.

What to change

Export a single still from the video (the first frame, or a representative moment) as a WebP at 1920×1080. Save it as site/assets/hero-video-poster.webp. Add the poster attribute to the <video> element. Also add preload="none" to prevent the browser from speculatively downloading the video on mobile.

// BEFORE
<video autoPlay muted loop playsInline
  style={{width:"100%", height:"100%", objectFit:"cover"}}>

// AFTER
<video autoPlay muted loop playsInline
  poster="site/assets/hero-video-poster.webp"
  preload="none"
  style={{width:"100%", height:"100%", objectFit:"cover"}}>
Critical
Page hero backgrounds: 1.3–2.7 MB JPEGs with no preload
cases.htmlteam.html+ others
Why it matters

CSS background-image is discovered only after the CSS is parsed — the browser cannot preload it via its speculative parser. These hero images are above-fold and should be the first thing a user sees, but they're queued behind CSS download and parse. A 2.7 MB JPEG at 2048px wide takes 2–8 seconds on a 4G connection.

What to change

Convert each hero background to WebP (target: under 200 KB at 1920px wide). Add a <link rel="preload"> tag in the <head> of each page. Use as="image" and type="image/webp". This tells the browser to fetch it at the highest priority before it even parses the CSS.

<!-- BEFORE: CSS background, no preload, 1.3 MB JPEG -->
.page-hero__bg-img {
  background: url('site/assets/cases-hero-bg.jpg') center / cover;
}

<!-- AFTER: add to <head> -->
<link rel="preload"
      href="site/assets/cases-hero-bg.webp"
      as="image"
      type="image/webp">
<!-- And update CSS to reference .webp -->

Critical
placeholder-case-executive.jpg: 2.4 MB at 4928 × 3264 px
sections.jsx → Cases cardscases.html → case grid
Why it matters

This image is displayed in a card at roughly 380px wide (homepage) or 320px wide (cases grid). The browser downloads all 2.4 MB at 4928px width regardless. That's over 40× more pixels than needed. It is also a JPEG — WebP would give roughly 30–40% further savings at equal quality.

What to change

Resize to 800×530px maximum and re-export as WebP at quality 82. Rename to placeholder-case-executive.webp. Expected output: ~60–90 KB. Then update the reference in sections.jsx and cases.html. If you want to serve different sizes per viewport, add srcset (covered in the Medium section).

// BEFORE — 2.4 MB JPEG at full camera resolution
<img src="site/assets/placeholder-case-executive.jpg"
     style={{width:"100%",height:"100%",objectFit:"cover"}} />

// AFTER — ~70 KB WebP, properly sized
<img src="site/assets/placeholder-case-executive.webp"
     width="800" height="530"
     loading="lazy"
     decoding="async"
     alt="C-suite digital strategy"
     style={{width:"100%",height:"100%",objectFit:"cover"}} />
High priority CLS + bandwidth

These don't block paint but cause measurable layout shift (CLS) and waste bandwidth on every page load. Fixable with attribute additions only — no new files needed.

High
No loading="lazy" on any <img> tag
sections.jsxteam.htmlall pages
Why it matters

Every <img> on the site loads at page-load time regardless of whether it's in the viewport. On the team page alone, this means 3+ portrait photos (each up to 1.9 MB) are downloaded before the user scrolls down. On a mobile connection this adds multiple seconds of avoidable network time to an already busy load.

What to change

Add loading="lazy" to every <img> that is below the fold — which in practice means everything except the first image visible above the fold on each page. Simultaneously add fetchpriority="high" to any image that is above the fold (e.g. a hero image used as an <img>).

// sections.jsx BEFORE — all images load at page load
<img src={c.img} alt=""
     style={{width:"100%",height:"100%",objectFit:"cover"}} />

// AFTER — below-fold case card images
<img src={c.img} alt=""
     loading="lazy"
     decoding="async"
     style={{width:"100%",height:"100%",objectFit:"cover"}} />

High
No width/height attributes — causes layout shift (CLS)
sections.jsxteam.htmlall <img> tags
Why it matters

Without explicit width and height attributes, the browser doesn't know the image's aspect ratio before it loads. This means it allocates zero height in the layout, then jumps when the image arrives — visible as content shifting down. This is measured as Cumulative Layout Shift (CLS), a Google ranking factor. The proof row logos and team portraits are the worst offenders since they load late.

What to change

Add width and height attributes matching the image's intrinsic dimensions to every <img>. The browser uses these to compute the aspect ratio — the CSS width: 100% still applies, so the image will still scale. The attributes just tell the browser how much space to reserve before the file arrives.

// BEFORE — browser allocates 0px height, shifts on load
<img src="site/assets/Emerce_Logo.png" alt=""
     style={{height: p.h, width: "auto", maxWidth: 150}} />

// AFTER — browser reserves space immediately (no shift)
<img src="site/assets/Emerce_Logo.png" alt=""
     width="1280" height="429"
     loading="lazy"
     style={{height: p.h, width: "auto", maxWidth: 150}} />
High
Team portraits: 1600–1920 px WebP, no srcset, displayed at ~280 px
team.html → JS-generated pcard__image
Why it matters

Alexandra Jankovich's portrait is 1600×1599 WebP (111 KB) and Tom Voskes is 1920×1920 (67 KB). They render at about 280px on desktop, meaning the browser downloads 5–6× more pixels than displayed. The format is already WebP, which is good — but the dimensions waste bandwidth, especially on mobile where the card may be ~160px wide.

What to change

Add loading="lazy" (all portraits are below the fold). Add width and height attributes. Optionally add a srcset serving a 320px version for mobile and a 640px version for desktop — this halves the bytes on mobile. The fallback Michiel Bos PNG also needs lazy loading and dims.

// team.html cardHTML() BEFORE
'<img src="' + imgPath + '" alt="' + p[0] + '" class="pcard__image">'

// AFTER
'<img src="' + imgPath + '" alt="' + p[0] + '" class="pcard__image"'
  + ' width="1600" height="1600" loading="lazy" decoding="async">'
High
Testimonial avatar hardcoded to one photo for all three quotes
sections.jsx → Credentials component
Why it matters

The Credentials section carousel shows three testimonials but the avatar is always home-testimonials-avatar.jpg — same photo regardless of whose quote is shown. When the attribution reads "Marieke Visser, CDO, Global Retail Group" but the photo is someone else, it's a credibility problem. This is primarily a content correctness issue but manifests as a broken image pattern.

What to change

Add an avatar field to each testimonial object in the TESTIMONIALS array. Each should point to the correct person's photo (or their company logo as a fallback). Add loading="lazy" and explicit width="52" height="52". The image is 30 KB at 720×720 — fine file size, just wrong person.

// BEFORE — same photo hardcoded
const TESTIMONIALS = [
  { quote: "...", name: "Marieke Visser", role: "CDO..." },
  { quote: "...", name: "Ivan Kotov",     role: "CCO..." },
];
// in JSX: src="site/assets/home-testimonials-avatar.jpg"

// AFTER — each person has their own avatar
const TESTIMONIALS = [
  { quote: "...", name: "Marieke Visser", role: "CDO...",
    avatar: "uploads/marieke-visser.webp" },
  { quote: "...", name: "Ivan Kotov", role: "CCO...",
    avatar: "uploads/ivan-kotov.webp" },
];
// in JSX: src={t.avatar} width="52" height="52" loading="lazy"
Medium priority Format modernisation

Switching from JPEG/PNG to WebP or AVIF is a straightforward server-side conversion that typically saves 30–50% bytes with no perceptible quality difference.

Medium
Hero backgrounds and case images still served as JPEG
site/assets/ — multiple .jpg files
Why it matters

WebP delivers equivalent visual quality at 25–34% smaller file sizes compared to JPEG. AVIF goes further (40–50%) but has slightly worse encoder support. All modern browsers (Chrome, Safari 14+, Firefox 65+) support WebP — it's safe to use as the primary format today. JPEG should be a fallback only.

What to change

Convert the JPEG files below to WebP. If browser compatibility with older Safari is a concern, use a <picture> element with WebP as the primary source and JPEG as fallback. For CSS backgrounds (hero pages), just replace the .jpg reference with .webp — no <picture> needed since CSS has no fallback mechanism; WebP support is ~98% of browsers.

<!-- <picture> pattern for editorial images -->
<picture>
  <source srcset="site/assets/placeholder-case-sustainability.webp"
          type="image/webp">
  <img src="site/assets/placeholder-case-sustainability.jpg"
       width="800" height="400"
       loading="lazy" alt="Sustainability project">
</picture>
Medium
Proof row logos served as PNG — could be WebP or SVG
sections.jsx → Credentials section PROOF array
Why it matters

PNG logos with transparency (Emerce, B-Corp, leading-employer, insead, imd-white, business-book-winner) need to stay transparent, so they can't become JPEG. But WebP supports alpha transparency and is typically 26% smaller than PNG. Even better: vector logos like B-Corp are ideal candidates for SVG, which is infinitely scalable, resolution-independent, and typically tiny in file size.

What to change

For each PNG logo: check if an SVG version exists (B-Corp and Emerce almost certainly do — check their brand kits). If SVG is available, use it. If not, convert to WebP with transparency. All logos already have small file sizes (20 KB max for Emerce), so this is low-risk. Priority: SVG > WebP > PNG.

Medium
No srcset for responsive image sizing
sections.jsxteam.html — images displayed at very different sizes on mobile vs desktop
Why it matters

Team portraits display at ~280px on desktop but ~full-width (~375px) on mobile — meaning mobile may download a larger image. Case cards go from ~380px on desktop to full-width on mobile. Without srcset, the browser always downloads the same file regardless of viewport. On a Retina screen it also downloads a 1× image when a 2× crop would look sharper.

What to change

Generate two sizes of each image: a 640px version and a 1280px version. Use srcset with a sizes hint. For team portraits shown in a 280px grid column, tell the browser the display size with sizes="(max-width: 640px) 50vw, 280px".

// Team portrait with srcset
<img
  src="uploads/alexandra-jankovich-640.webp"
  srcset="uploads/alexandra-jankovich-640.webp 640w,
          uploads/alexandra-jankovich-1280.webp 1280w"
  sizes="(max-width: 640px) 50vw, 280px"
  width="640" height="640"
  loading="lazy"
  alt="Alexandra Jankovich"
  class="pcard__image">
Low priority Polish

Minor improvements with negligible performance impact on their own, but good practice and worth doing in a single pass.

Low
Missing alt text on case card images
sections.jsx → Cases → <img alt="">
Why it matters

Empty alt="" is correct for purely decorative images — but case card images are the visual representation of a specific case study. Screen readers skip them entirely. Adding descriptive alt text (e.g. "Logistics operations at TBI Holdings") improves accessibility and gives search engines context for the image content.

What to change

Add an alt field to each entry in the CASES array in sections.jsx with a 5–10 word description of the image. Use alt={c.alt} on the <img>. Keep alt="" for logos and purely decorative images.

Low
No decoding="async" on below-fold images
All <img> tags
Why it matters

Image decoding (converting compressed bytes into pixels) can block the main thread. decoding="async" lets the browser decode the image off the main thread, reducing jank during scroll-in animations. Useful alongside loading="lazy" on images that animate in.

What to change

Add decoding="async" to all images that also get loading="lazy". For LCP images (above fold), use decoding="sync" (default) to ensure they display immediately without an async decode cycle.

Low
No font-display or icon preconnect hints
All HTML pages <head>
Why it matters

Not strictly image-related, but in the same loading budget category: the Manrope font (Google Fonts) and Lucide CDN are loaded without a <link rel="preconnect"> hint. The browser must complete a DNS lookup + TLS handshake before downloading these, adding ~150–300ms. On text-heavy pages, this causes a flash of invisible or unstyled text (FOIT/FOUT).

What to change

Add preconnect hints for Google Fonts and unpkg at the very top of <head>, before any other resource links.

<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="preconnect" href="https://unpkg.com">

Recommended implementation order

Do these in order — each step builds on the last and the biggest performance gains come first.

1
Resize + convert the 2.4 MB case image
Export placeholder-case-executive.jpg as WebP at 800×530, quality 82. Update the reference in sections.jsx and cases.html. Immediate ~96% file size reduction for this image.
2
Add poster frame to hero video
Export a still from home-hero-video.mp4 as WebP. Add poster and preload="none" to the <video> tag in hero.jsx. Eliminates the blank black screen on homepage load.
3
Convert hero background JPEGs to WebP + add preload hints
Convert cases-hero-bg.jpg, team-hero-bg.jpg, hero-bg.jpg to WebP. Add <link rel="preload"> in the <head> of each corresponding page. Target under 200 KB per file.
4
Add loading="lazy" + width/height to all <img> tags
One pass through sections.jsx and team.html. Lazy-load everything below the fold. Add intrinsic dimensions to every image to eliminate CLS. This can be done in a single editing session — no new files needed.
5
Replace remaining JPEG editorial images with WebP equivalents
Convert placeholder-case-sustainability.jpg and other JPEG editorial images. Also convert PNG logos to WebP (or find SVG originals). Update file references in JSX and HTML.
6
Fix testimonial avatars + add preconnect hints
Add per-person avatar fields to the TESTIMONIALS array. Add preconnect hints for Google Fonts and unpkg at the top of every page's <head>.
7
Add srcset + sizes for responsive image delivery
Generate 640px and 1280px variants of team portraits and case card images. Add srcset and sizes attributes. This is the most effort-intensive step — best done when the final photography set is confirmed.
